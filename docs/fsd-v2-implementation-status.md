# EnergiTrack FSD v2.0 implementation status

Status updated 20 November 2026. This tracks the implementation plan discussed for FSD v2.0. A checked build or acceptance suite is evidence only for the cases it actually covers.

Buildings has list, detail, new, and edit routes. Role-by-role route audit is still outstanding. |

## Changes in this revision

- Added `ImportJob.previewCsv` and an additive migration at `backend/prisma/migrations/20261118153000_import_preview_csv/`.
- Added multipart preview and job-ID confirmation while preserving the JSON import endpoint for existing callers.
- Kept preview CSV private: list/detail responses omit the stored file contents.
- Tightened Data Sources editability so sources with legacy integration credentials cannot be changed through the simplified catalog.
- Updated the Vue import form to upload multipart data and confirm the saved preview.
- Added domain acceptance coverage for the saved-preview flow and generated endpoint-specific OpenAPI schemas.
- Added six selectable report types with quality, alert, and audit snapshots plus dynamic CSV/XLSX/PDF columns. Report history can search and sort by type.
- Fixed report history search to use the persisted `ReportJob.type` field rather than a non-existent title column.
- Added dashboard filters, site energy distribution, recent activity from the permission-scoped audit log API, and four Site Detail tabs using existing API data.
- Added Building detail/new/edit routes, row navigation, and building status editing; added tabs across the meter detail and its configuration/maintenance routes.
- Added Tailwind CSS v4/Vite and shadcn-vue configuration, theme tokens, and shared Button/Input components; applied them to dashboard actions and authentication forms.
- Fixed login session persistence by awaiting the session-store save before returning success. The local seed now upserts one account for each built-in role, with no “Demo” label and a shared `developer123` password; production seeding is blocked. Verified the role accounts across the local API and login-to-`/auth/me` in isolated acceptance.
- Seed reruns now detach and deactivate obsolete built-in-role accounts in the seed-owned `@energitrack.local` namespace, so they cannot log in or appear in organization members. User rows remain for audit history; a seed assertion requires all seven canonical accounts to have active memberships.
- Added versioned persistent hourly, daily, and monthly aggregates with site-timezone boundaries, expected/observed counts, completeness, and backfill requeue migration. Extended monitoring responses and OpenAPI fields; added unit cases for DST and calendar boundaries plus isolated acceptance assertions for rollup values and reaggregation versions.
- Standardized catalog pagination query names to FSD `sortBy`/`sortOrder` while keeping the old aliases compatible; documented the fields in OpenAPI, retained them in page metadata, and added smoke assertions for canonical and legacy requests.
- Made Data Sources follow browser back/forward changes to its page, search, and sort URL state without resetting a page restored from history.
- Updated the 30-screen route registry so screen #28 resolves to Data Sources, preserving the previous Integrations URL as a gated compatibility route.
- Added server-side pagination, search, and sorting to the User Management member table, a distinct no-results message, and retry action for paginated list errors; the acceptance smoke matrix now includes Data Sources, forecast drivers, and tariff assignments.
- Preserved restored page numbers when navigation history updates search and page state together; changing a filter interactively still returns the list to page 1.
- Extracted workspace shell, dashboard, and Site detail presentation from `App.vue`; extracted data-source, CSV-preview, and forecast route groups from `server.ts`.
- Applied the three pending additive data-source/import migrations to the local `energytrack` database on 19 November 2026; `prisma migrate status` reports up to date, `ImportJob.previewCsv` exists, and `/health/live` plus `/health/ready` return 200.
